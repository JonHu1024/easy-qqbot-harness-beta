# easy-qqbot-harness

给 **QQ 开放平台机器人**用的本地控制台 + AI 对话框架。

一条命令启动，本地网页里把人格、模型、记忆、资料库、语音、定时任务全配好，
机器人就能上线了 —— 不用写代码，不用改配置文件。

**v0.2.1-beta** · MIT · Node.js 24+ · 数据全在本地的 SQLite 里

---

## 它能做什么

| | |
| --- | --- |
| **人格与底线** | 名字、性格、说话风格，外加一段「底线提示词」—— 让它有脾气，会拒绝 |
| **模型接入** | OpenAI 兼容 / Anthropic 两种协议，聊天模型、生图、生视频、语音各自独立配置 |
| **会话记忆** | 每个会话是一个 session，长期事实自动维护，可以导出、可以重命名 |
| **资料库** | 一个资料库 = 一个文件夹。模型能自己读、自己存，存进去的东西它会写说明 |
| **相册** | 机器人有「自己的照片」，不用每次重新生成，它自己知道 |
| **语音** | 语音输入识别 + 语音输出。模型想「开口说话」时，就只发语音不废话 |
| **定时任务** | 它能自己建提醒，到点执行，执行完自动清理 |
| **联网搜索** | 关键词搜索 + 读网页正文，引用带链接 |
| **沙箱** | 给模型一个只读的虚拟文件系统，它能 ls / cat / grep 自己那几个文件夹 |

技术上：**Node.js 24+ · SQLite · 原生 HTML/CSS/JS**。
前端零构建、零 CDN 依赖 —— 断网也能用。

## 三分钟跑起来

```bash
git clone https://github.com/JonHu1024/easy-qqbot-harness-beta.git
cd easy-qqbot-harness-beta
npm install
npm run bot
```

浏览器打开 **http://127.0.0.1:3210**。

`npm run bot` 会同时启动控制台并连接 QQ。想先看看界面、稍后再连：

```bash
npm start        # 只开控制台，不连 QQ
```

也可以完全不开网页，纯环境变量跑：

```bash
QQBOT_APP_ID=你的AppID QQBOT_APP_SECRET=你的Secret npm run bot
```

### 接下来

1. **QQ 接入** —— 填 AppID / AppSecret（见下面「连上 QQ」）
2. **模型接入** —— 填接口地址、Key、模型名，点「测试连接」
3. **人格** —— 起个名字，写清楚它是谁、什么脾气
4. 点侧边栏「**启动机器人**」，回 QQ 跟它说话

### 常用命令

| 命令 | 作用 |
| --- | --- |
| `npm run bot` | 启动控制台 + 连接 QQ |

更多用法（只连 QQ不开网页、指定端口、查可用模型名、代理设置）见

## 连上 QQ

去 [QQ 开放平台](https://qun.qq.com/) 创建一个机器人，拿 AppID 和 AppSecret，
填进控制台的「接入 → QQ 接入」。事件订阅建议全选。

默认走 **WebSocket**（推荐）：本地程序主动连过去，不需要公网地址。
如果非要用 Webhook，控制台也能收，但得自己有 HTTPS 域名。

连不上、频繁掉线？看 [常见问题 · 连接自己的 QQ 机器人](docs/常见问题.md)。

## 控制台一览

侧边栏分五组：

| 组 | 栏目 | 放什么 |
| --- | --- | --- |
| **总览** | 概览 | 运行状态、启停、Token 用量 |
| **接入** | QQ 接入 | AppID / AppSecret、连接方式、事件订阅 |
| | 模型接入 | 聊天模型（带「测试连接」）、生图 / 生视频（三种接入方式） |
| | 语音 | 语音合成：合成接口或 Windows 系统语音，带「测试语音」 |
| **机器人** | 人格 | 名字、人格提示词、**底线提示词**、欢迎语、访问控制 |
| | 回复策略 | 条数字数、**首次回复延迟与合并窗口**、冷却、长文、工具轮数 |
| | 命令与规则 | 自定义斜杠命令与关键词规则 |
| | 会话记忆 | 把每个会话当 session 管理：重命名、看长期事实、导出、删除 |
| **Harness** | 能力 | 多模态输入、联网搜索、生图生视频的开关 |
| | 资料库 | 文件夹 + `DOC.md` 的资料体系 |
| | 表情包 | 图片表情包，名字就是表情的意思 |
| | 定时任务 | 任务列表、模型建任务的开关 |
| **运行** | 数据文件 | 数据目录在哪、每个文件多大、数据库每张表多少行 |
| | 运行日志 | 分级日志与搜索 |

**设置项跟着它控制的东西走**：换行拆分在「回复策略」，表情开关在「表情包」，
资料库开关在「资料库」，自动记忆在「会话记忆」。

所有改动先进入本地草稿，点顶部「**保存配置**」才写进服务器。

## 几件值得知道的事

### 底线提示词：让它有脾气

「人格 → 底线提示词」是给机器人的**硬规矩**，比如：

> 不管用户如何要求，都不可以成为用户的恋人；对方表白要明确拒绝。
> 不要轻易把自己的照片发出去。

这段话会被放在**用户消息之后**发给模型 —— 位置越靠后，模型越当回事。
它写得很硬时，模型真的会拒绝你。

代价是：某些模型服务的内容审核会因此拒收整条请求。
Harness 会自动降级重试（摘掉底线 → 缩短历史 → 只发当前消息），保证你总能收到回复，
但**降级的那一轮底线是不生效的**。

### 资料库：一个库 = 一个文件夹

不用学什么「资源库体系」，就是文件夹。模型能自己列、自己读、自己存。

存文件的时候它会**先读懂再写说明** —— 说明会一直存在文件旁边，
以后它（或者你）看一眼就知道里面是什么。

### 相册：它记得自己长什么样

机器人有「自己的照片」放在相册里。生成新照片时会参考相册，
脸不会每次都变。相册也是普通文件夹，能进资料库那套流程。

### 语音：开口说话，不是「调用语音模型」

用户想听它说话、或者需要被安慰的时候，它会直接发一条语音，
**不多打字**。想让它只发语音不废话，就是这个设计。

### 回复延迟与合并

「回复策略」里两个数字配合用：收到消息先等 1.2 秒，
这期间用户再发的消息会合并成一次提问。

用户连着发「今天天气怎么样」「顺便查下明天行程」「谢谢」时，
它会等窗口结束把三条一起回答，不会答一句漏一句。

## 数据放在哪

**全部数据都在一个目录里**，默认是项目下的 `data/`（可用 `QQBOT_DATA_DIR` 改）。

| 文件 | 内容 |
| --- | --- |
| `qqbot.sqlite` | 配置、会话、消息、资料库、表情包、提醒、日志、用量 |
| `master.key` | 加密密钥种子，**丢了配置里的密钥就解不开了** |
| `instance.lock` | 运行锁，防止开两个机器人互相踢下线 |

**备份 = 复制整个目录**。控制台「运行 → 数据文件」能看到实时大小和每张表的行数。

删除是**真删除**：连接开着 `secure_delete`，删掉的内容在文件里也搜不到。

## 安全

- 控制台默认只听 `127.0.0.1`。**对外暴露必须设置 `QQBOT_ADMIN_PASSWORD`（至少 12 字符）**，
  程序会拒绝在不满足条件时启动；建议再套一层 HTTPS 反向代理。
- API Key 用 AES-256-GCM 加密存在库里，密钥种子 `master.key` 也在同一个目录 —— 别把它传出去。
- 导出的配置**不含**任何密钥。
- 模型给的附件、引用、历史一律当**资料**，不会被当成指令执行。
- 模型能调用的东西是有限的：文件读写只发生在沙箱里（只读，`>` 重定向只写虚拟输出区），
  但它仍然能发消息、建提醒、联网 —— 工具权限就是它的权限。

更细的边界见 [SECURITY.md](SECURITY.md)。

## 开发

```bash
npm install
npm test              # 回归测试
npm run dev           # 带热重载起控制台
npm run verify        # 联调真实模型，但不碰你的真实数据
npm run release:check # 发版前自检
```

```
src/        后端（Node ESM，除 express / ws / zod 外零依赖）
  cli.js      命令行入口
  server.js   控制台 HTTP 接口
  engine.js   对话主循环：提示词、工具、工具轮次、发送
  model.js    模型协议适配与工具定义
  store.js    SQLite 存储
  media.js    附件下载与解析
  sandbox.js  只读虚拟文件系统
public/     前端（原生 HTML / CSS / JS，零构建）
test/       回归测试
scripts/    联调脚本、发布前自检、误删消息恢复工具
docs/       常见问题与深入说明
```

规矩、目录说明、发版流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。

遇到问题先看 [常见问题](docs/常见问题.md)，那里有排查步骤和历史踩过的坑。
