# easy-qqbot-harness

给 **QQ 开放平台机器人**用的本地控制台 + AI 对话框架。

一条命令启动，本地网页里把人格、模型、记忆、资料库、语音、定时任务全配好，
机器人就能上线了 —— 不用写代码，不用改配置文件。

**v0.2.1-beta** · MIT · Node.js 24+ · 数据全在本地的 SQLite 里

---

## 它能做什么

先看一眼全貌：

| | |
| --- | --- |
| **人格与底线** | 性格、说话风格，外加一段「底线提示词」—— 让它有脾气，会拒绝 |
| **模型接入** | OpenAI 兼容 / Anthropic 两种协议；聊天、生图、生视频、语音各自独立配置 |
| **会话记忆** | 每个会话一个 session，长期事实自动维护，可导出、可重命名 |
| **资料库** | 一个库 = 一个文件夹。模型能自己读、自己存，存进去的东西它会写说明 |
| **相册** | 机器人有「自己的照片」，生新图时参考它，脸不会每次都变 |
| **多模态** | 图片、PDF、语音都能进对话，也能存进资料库 |
| **语音** | 语音识别 + 语音合成。它想「开口说话」时，只发语音不废话 |
| **定时任务** | 它能自己建提醒，到点执行，执行完自动清理 |
| **联网搜索** | 关键词搜索 + 读网页正文，引用带链接 |
| **表情包** | 图片表情包，名字就是表情的意思 |
| **沙箱** | 只读虚拟文件系统，模型能 ls / cat / grep 自己的资料库 |
| **消息工程** | 首次延迟、消息合并、冷却、长文授权、输出中通知……聊天的节奏都能调 |

下面挑几个真正有意思的说细一点。

### 人格：它得有个性，还得有底线

- **人格提示词** —— 身份、语气、说话习惯、禁忌。写「你是一个助手」等于没写；
  写清楚它是谁、什么脾气、什么话不能说，效果完全不一样。
- **底线提示词** —— 给它的硬规矩。这段话会被放在**用户消息之后**发给模型，
  位置越靠后模型越当回事。它写得够硬时，模型真的会拒绝你。
- **它能推回去** —— 遇到明显不合理的要求，它可以不照做，还能拿出理由反驳。
- **它有时间感** —— 当前时间会进系统提示，所以它说「今天」的时候知道是哪天。
  不用你自己往提示词里塞日期。

### 记忆：它记得你说过什么

**每个会话是一个独立的 session**，各自记自己的事。

- 对话历史默认留最近若干轮，可以调
- 自动抽取长期事实（「他叫 Jon」「他在成都上班」），下次它还记得
- 会话可以改名、导出成 JSON、单独删除
- 记忆有保质期，过期的自动清

关掉「会话记忆 → 自动记忆」，它就只看当前这一轮。

### 资料库：它能读自己的文件，也能往里存

不用学什么「资源库体系」——**一个库就是一个文件夹**。

每个文件夹都有一份 `DOC.md`，是这个库的说明书：什么时候该翻它、里面大概有什么。
模型先读说明书，再决定要不要读具体文件。

它能做的：

| 工具 | 干什么 |
| --- | --- |
| `list_notes` | 列出有哪些库、里面有什么 |
| `read_note` | 读一个库的说明和文件 |
| `save_file` | 把这次收到的附件存进某个库 |
| `save_note` | 把一段内容写成文件存进去 |
| `describe_file` | 给存进去的文件写说明（存完必做） |

**存进去的东西它自己会写说明。** 存完返回一段预览，模型读完要写一句话
（这是什么、以后什么时候该翻它）再写回去。所以半年后你翻这个库，
文件旁边就有一句话说明，不用自己记。

### 相册：它知道自己长什么样

机器人有「自己的照片」放在相册里。**生成新照片时会带上相册里的参考图**，
脸不会每次都变 —— 这是纯文字生图做不到的事。

相册也是普通文件夹，能进资料库那套流程：它能自己列、自己找、自己发。

### 多模态：图片、PDF、语音都能进来

- **图片** —— 走视觉模型，能「看」；也可以只当附件存起来
- **PDF** —— 正文能提取就提取进上下文；提不出来的（比如扫描件）也**照样存得下来**，
  变成资料库里的一个文件
- **语音** —— 转成文字进上下文
- **附件上限分开算** —— 「塞进上下文的体积」和「存进库的体积」是两个数，
  大文件不能进上下文但可以入库

### 语音：开口说话，不打字

用户想听它说话、或者需要被安慰的时候，它会直接发一条语音，**正文一个字都没有**。
提示词里写死了这条规则，不是靠模型自觉。

语音合成可以接 API（OpenAI 兼容的 `/audio/speech`），也可以用 Windows 系统语音，
面板里有「测试语音」按钮。

### 联网：能查、能读、能引用

- **搜索** —— DuckDuckGo → 必应 → 维基百科 自动回退，连不上就换下一个
- **读网页** —— 抓正文，不是把 HTML 糊给模型
- **引用带链接** —— 回答里能点到来源

### 定时任务：它能自己立提醒

「你明天上午十点提醒我交房租」——它会自己建一个任务，到点执行，执行完自动清理。
不用你在控制台点。

它建任务的开关在「定时任务」面板里，可以关掉（关了它就只会口头答应你）。

### 表情包与自定义命令

- **表情包** —— 传几张图，给它们起名字（名字就是表情的意思，比如「开心」「无语」）。
  它觉得该发表情的时候会自己发。
- **斜杠命令** —— `/帮助`、`/状态` 这些。命令**不等待**，立即回应。
- **关键词规则** —— 命中关键词就用固定回复，不消耗模型。

### 消息工程：聊天的节奏都能调

这部分决定了它像不像真人：

| 设置 | 效果 |
| --- | --- |
| **首次回复延迟** | 收到消息先等 1.2 秒再答 —— 太快会显得像机器人 |
| **消息合并窗口** | 这期间用户连发的几条合并成一次提问，不会答一句漏一句 |
| **多条回复之间的间隔** | 一次回答拆成多条时，每条隔多久 |
| **用户冷却** | 同一个人两次触发之间的最小间隔 |
| **换行拆分** | 按段落拆成多条消息发 |
| **输出中通知** | 打字时显示「对方正在输入…」 |
| **自然停顿** | 句与句之间随机停顿一点 |
| **长文授权** | 长回答要走冷却，避免刷屏 |

### 靠得住：降级、重连、别把话憋死

这是花最多时间打磨的部分：

- **模型服务拒收时自动降级** —— 遇到「输入含敏感内容」会三级降级重试
  （摘掉底线 → 缩短历史 → 只发当前消息），**保证你总能收到回复**，
  而不是整轮失败、用户什么都收不到
- **附件被接口拒绝时降级** —— 换个说法重试，而不是报错
- **工具调用有上限** —— 防止模型陷在死循环里刷工具
- **QQ 网关自动重连** —— 会话过期是正常轮换，自动恢复；真断了按指数退避重试
- **删了就是删了** —— 数据库开着 `secure_delete`，删掉的内容在文件里也搜不到

### 数据与安全

- **数据全在本地** —— 一个 SQLite 文件 + 一个密钥文件，备份就是复制目录
- **API Key 加密存** —— AES-256-GCM，密钥种子在 `master.key`
- **控制台默认只听本机** —— 对外暴露必须设密码（≥12 字符），否则拒绝启动
- **模型给的附件、网页、历史一律当资料** —— 不会被当成指令执行
- **沙箱只读** —— 模型能读资料库，但写不进你的磁盘

技术上：**Node.js 24+ · SQLite · 原生 HTML/CSS/JS**。
前端零构建、零 CDN 依赖 —— 断网也能用。

## 适合谁

**适合**：想给自己或朋友做一个有性格的 QQ 机器人；想给 Bot 加记忆、资料库、
相册这些「活人感」的东西；愿意自己改提示词调教它的。

**不太适合**：要做高并发、多租户的商用平台（这是单机自用工具）；
不想碰命令行（第一次总要跑一条 `npm install`）。

## 三分钟跑起来

```bash
git clone https://github.com/JonHu1024/easy-qqbot-harness-beta.git
cd easy-qqbot-harness-beta
npm install
npm run bot
```

浏览器打开 **http://127.0.0.1:3210**。

`npm run bot` 会同时启动控制台并连接 QQ。想先看看界面、稍后再连：

```bash
npm start        # 只开控制台，不连 QQ
```

也可以完全不开网页，纯环境变量跑：

```bash
QQBOT_APP_ID=你的AppID QQBOT_APP_SECRET=你的Secret npm run bot
```

### 接下来

1. **QQ 接入** —— 填 AppID / AppSecret（见下面「连上 QQ」）
2. **模型接入** —— 填接口地址、Key、模型名，点「测试连接」
3. **人格** —— 起个名字，写清楚它是谁、什么脾气
4. 点侧边栏「**启动机器人**」，回 QQ 跟它说话

### 常用命令

| 命令 | 作用 |
| --- | --- |
| `npm run bot` | 启动控制台 + 连接 QQ |
| `npm start` | 只启动控制台 |
| `npm run dev` | 带热重载地起控制台（改前端代码时用） |
| `npm test` | 跑测试 |
| `npm run verify` | 不碰真实数据地联调一次真实模型 |
| `npm run release:check` | 发版前自检（查密钥、跑测试、查语法） |

更多用法（只连 QQ 不开网页、指定端口、查可用模型名、代理设置）见
[常见问题](docs/常见问题.md)。

## 连上 QQ

去 [QQ 开放平台](https://qun.qq.com/) 创建一个机器人，拿 AppID 和 AppSecret，
填进控制台的「接入 → QQ 接入」。事件订阅建议全选。

默认走 **WebSocket**（推荐）：本地程序主动连过去，不需要公网地址。
如果非要用 Webhook，控制台也能收，但得自己有 HTTPS 域名。

连不上、频繁掉线？看 [常见问题 · 连接与掉线](docs/常见问题.md#12-连接与掉线)。

## 控制台一览

侧边栏分五组：

| 组 | 栏目 | 放什么 |
| --- | --- | --- |
| **总览** | 概览 | 运行状态、启停、Token 用量 |
| **接入** | QQ 接入 | AppID / AppSecret、连接方式、事件订阅 |
| | 模型接入 | 聊天模型（带「测试连接」）、生图 / 生视频（三种接入方式） |
| | 语音 | 语音合成：合成接口或 Windows 系统语音，带「测试语音」 |
| **机器人** | 人格 | 名字、人格提示词、**底线提示词**、欢迎语、访问控制 |
| | 回复策略 | 条数字数、**首次回复延迟与合并窗口**、冷却、长文、工具轮数 |
| | 命令与规则 | 自定义斜杠命令与关键词规则 |
| | 会话记忆 | 把每个会话当 session 管理：重命名、看长期事实、导出、删除 |
| **Harness** | 能力 | 多模态输入、联网搜索、生图生视频的开关 |
| | 资料库 | 文件夹 + `DOC.md` 的资料体系 |
| | 表情包 | 图片表情包，名字就是表情的意思 |
| | 定时任务 | 任务列表、模型建任务的开关 |
| **运行** | 数据文件 | 数据目录在哪、每个文件多大、数据库每张表多少行 |
| | 运行日志 | 分级日志与搜索 |

**设置项跟着它控制的东西走**：换行拆分、长文授权、输出中通知、自然停顿、工具轮数在「回复策略」；
表情开关在「表情包」；资料库开关在「资料库」；自动记忆在「会话记忆」；
联网搜索、多模态、生图生视频在「能力」。

所有改动先进入本地草稿，点顶部「**保存配置**」才写进服务器。

## 数据放在哪

**全部数据都在一个目录里**，默认是项目下的 `data/`（可用 `QQBOT_DATA_DIR` 改）。

| 文件 | 内容 |
| --- | --- |
| `qqbot.sqlite` | 配置、会话、消息、资料库、表情包、提醒、日志、用量 |
| `master.key` | 加密密钥种子，**丢了配置里的密钥就解不开了** |
| `instance.lock` | 运行锁，防止开两个机器人互相踢下线 |

**备份 = 复制整个目录**。控制台「运行 → 数据文件」能看到实时大小和每张表的行数。

删除是**真删除**：连接开着 `secure_delete`，删掉的内容在文件里也搜不到。

## 安全

- 控制台默认只听 `127.0.0.1`。**对外暴露必须设置 `QQBOT_ADMIN_PASSWORD`（至少 12 字符）**，
  程序会拒绝在不满足条件时启动；建议再套一层 HTTPS 反向代理。
- API Key 用 AES-256-GCM 加密存在库里，密钥种子 `master.key` 也在同一个目录 —— 别把它传出去。
- 导出的配置**不含**任何密钥。
- 模型给的附件、引用、历史一律当**资料**，不会被当成指令执行。
- 模型能调用的东西是有限的：文件读写只发生在沙箱里（只读，`>` 重定向只写虚拟输出区），
  但它仍然能发消息、建提醒、联网 —— 工具权限就是它的权限。

更细的边界见 [SECURITY.md](SECURITY.md)。

## 开发

```bash
npm install
npm test              # 回归测试
npm run dev           # 带热重载起控制台
npm run verify        # 联调真实模型，但不碰你的真实数据
npm run release:check # 发版前自检
```

```
src/        后端（Node ESM，除 express / ws / zod 外零依赖）
  cli.js      命令行入口
  server.js   控制台 HTTP 接口
  engine.js   对话主循环：提示词、工具、工具轮次、发送
  model.js    模型协议适配与工具定义
  store.js    SQLite 存储
  media.js    附件下载与解析
  sandbox.js  只读虚拟文件系统
public/     前端（原生 HTML / CSS / JS，零构建）
test/       回归测试
scripts/    联调脚本、发布前自检、误删消息恢复工具
docs/       常见问题与深入说明
```

规矩、目录说明、发版流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。

遇到问题先看 [常见问题](docs/常见问题.md)，那里有排查步骤和历史踩过的坑。
