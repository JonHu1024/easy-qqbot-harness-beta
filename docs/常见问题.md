## 1. 回复延迟与消息合并

「回复策略」里有两个互相配合的数值：

| 配置 | 含义 | 默认 |
| --- | --- | --- |
| **首次回复延迟**（`bot.firstReplyDelayMs`） | 收到消息后**先等这么久**再开始回答 | 1200 ms |
| **消息合并窗口**（`bot.mergeWindowMs`） | 这段时间内到达的**多条消息合并成一次提问** | 2500 ms |
| **多条回复之间的间隔**（`bot.replyDelayMs`） | 一次回答拆成多条消息时，每条之间隔多久 | 800 ms |
| **用户冷却**（`bot.cooldownMs`） | 同一个人两次触发之间的最小间隔 | 1000 ms |

效果：用户连着发「今天天气怎么样」「顺便帮我查下明天的行程」「谢谢」时，
机器人会等窗口结束，把三条合并成一次提问交给模型 —— 不会答一句漏一句。

**斜杠命令不等待**，立即回应。命令需要即时反馈，等一下就失去意义了。

嫌慢就把首次延迟调小（比如 500），但调太小了容易在用户还没说完时就抢答。

### 跑在服务器上的其它启动方式

```bash
node src/cli.js start --no-console        # 只连 QQ，不开网页
node src/cli.js start --port 8080 --host 0.0.0.0
node src/cli.js models                    # 查当前 Key 能用的图片 / 视频模型名
```

环境变量：`QQBOT_APP_ID`、`QQBOT_APP_SECRET`、`QQBOT_DATA_DIR`、`QQBOT_ADMIN_PASSWORD`、
`QQBOT_PUBLIC_ORIGIN`、`QQBOT_POKE_TOKEN`、`QQBOT_TRACE`、`HOST`、`PORT`。

## 2. 会话记忆

「会话记忆」面板把**每个会话当成一个 session** 管：

- 自动记下对话历史，默认留最近 12 轮
- 抽取长期事实（「他叫 Jon」「他在成都上班」），下次还在
- 可以给会话改名字、导出成 JSON、单独删除
- 记忆默认留 30 天，过期的自动清

「Harness → 能力」里可以关掉自动记忆；关掉之后模型就只看当前这轮。

**删会话是不可逆的。** 控制台会先记一条日志说明「什么时候删的、删了多少条」，
但内容本身不会留在数据库里 —— 删掉的东西就是删掉了。

## 3. 资料库

资料库的模型很简单：**一个库 = 一个文件夹**。

每个文件夹里都有一份 `DOC.md`，是这个文件夹的说明书：
什么时候该翻它、里面大概有什么。模型先读 `DOC.md`，再决定要不要读具体文件。

模型能做的：

| 工具 | 干什么 |
| --- | --- |
| `list_notes` | 列出有哪些文件夹、里面有什么 |
| `read_note` | 读一个文件夹里的说明和文件 |
| `save_file` | 把这次收到的附件存进某个文件夹 |
| `save_note` | 把一段内容写成文件存进去 |
| `describe_file` | 给存进去的文件写说明（存完必做） |

**存进去的东西它自己会写说明。** 存完会返回一段 `preview`，模型读完要写一段
说明（这是什么、里面有什么、以后什么时候该翻它），再调 `describe_file` 写回去。
所以半年后你翻这个库，文件旁边就有一句话说明，不用自己记。

## 4. 生成的多种接入方式

生图、生视频各有三种接法，在「模型接入」里选：

1. **OpenAI 兼容接口** —— 走 `/v1/images/generations` 这类标准路径
2. **Agnes 等自建站** —— 图片转图片走 `POST /images/edits`（multipart）
3. **不配** —— 关闭这项能力，模型也不会假装自己能画

**图片转图片的坑**：`image` 字段只认 data URL，写成 `images[]` 或 `reference_image`
会直接 400。Harness 已经处理好了，不用你操心。

**每种服务都有不同的规矩**：有的服务 `image` 只收 data URL，有的收远程 URL；
有的不接受 `file` 片段（`file must have a file_id or file_data`）。
碰到这些，Harness 会自动降级成「只发文字描述重试」，不会整轮失败。

## 5. 语音

「语音」面板有两块：

- **语音合成** —— 合成接口（OpenAI 兼容的 `/audio/speech`）或 Windows 系统语音
- **语音识别** —— 用户发语音过来时转成文字

提示词里已经写死了：**模型想「开口说话」的时候，就只发语音，不打字。**
所以用户说「用语音跟我说句晚安」，它回一条语音，正文一个字都没有。

如果你希望它说完话再补一段文字，把「回复策略 → 语音回复时附带文字」打开。

## 6. 沙箱

模型能操作的文件系统是**只读**的虚拟目录，长这样：

```
/files     ← 资料库里的文件夹
/memes     ← 表情包
```

可用的命令：`pwd cd ls find cat head tail grep tree wc du stat file od echo sort uniq nl cut tr sed awk basename dirname tac rev which help`

**它不是完整的 shell**：不支持 `for` / `while` / `if`、变量、命令替换。
一次写一条简单命令就行，可以用 `|` 管道和 `>` 重定向
（`>` 写进虚拟输出区，不会真的落盘）。

路径找不到时，错误信息里会**把这个文件夹里有什么列出来** —— 模型不用再一个一个猜。

## 7. 排查「牛头不对马嘴」

按这个顺序查：

1. **它看到的内容和你以为的不一样吗** —— 打开「运行日志」，看这一轮实际发出去的
   消息体。附件有没有传进去、历史带了几轮，一目了然。
2. **人格提示词写清楚了吗** —— 「你是一个助手」这种写法等于没写。
   写清楚身份、语气、它关心什么。
3. **底线提示词是不是太硬** —— 太硬的底线会让某些模型服务直接拒收整条请求。
4. **上下文是不是被截断了** —— 历史轮次调小会让它「记不住事」。

日志里带 `[trace]` 的是网关协议细节（需要 `QQBOT_TRACE=1`），排查掉线时用。

## 8. 图片发不出去

三个常见原因：

1. **模型压根没调生图工具** —— 它只是嘴上说「我给你画一张」。
   Harness 会检测到这种情况并要求它重做。
2. **图片生成服务返回的不是图片** —— 有些接口返回的是 URL 或者任务 ID，
   得先轮询再下载。控制台「模型接入」里点「测试连接」能看出是哪一种。
3. **QQ 侧拒绝** —— c2c 单聊每天能主动发几条有上限，群聊更严。
   连续发图容易撞限。

## 9. 让模型更像人的几件事

**① 生成新照片时参考相册**

「相册」里放的是机器人「自己的照片」。生成新照片时会带上相册里的参考图，
脸不会每次都变。相册也是普通文件夹，能进资料库那套流程。

**② 底线提示词放在用户消息之后**

底线越靠近模型输出的位置，模型越当回事。
Harness 把它放在用户消息**后面** —— 不是开头当免责声明，是结尾当「不能越的线」。

**③ 给模型时间感**

系统提示里带了当前时间，所以它说「今天」的时候知道是哪天。
不用自己往提示词里塞日期。

## 10. 数据文件与删除

所有数据都在一个目录，默认 `data/`（`QQBOT_DATA_DIR` 可以改）：

| 文件 | 内容 |
| --- | --- |
| `qqbot.sqlite` | 配置、会话、消息、资料库、表情包、提醒、日志、用量 |
| `master.key` | 加密密钥种子 —— **丢了就解不开配置里的密钥** |
| `instance.lock` | 运行锁，防止开两个机器人互相踢下线 |

控制台「运行 → 数据文件」能看到实时大小和每张表的行数。

**备份 = 复制整个目录**（`master.key` 也要一起）。

**删除是真删除**：连接开着 `PRAGMA secure_delete=ON`，
删掉的行会被就地清零，再 `VACUUM` 把空间还给文件系统 ——
用 `grep` 在数据库文件里搜不到删掉的原文。

## 11. 模型服务说「输入含敏感内容」

某些模型服务（尤其是带内容审核的）会返回 `HTTP 500 input new_sensitive`，
意思是「你发来的这整条请求里有敏感内容，我拒绝处理」。

**常见原因**：底线提示词本身触发了审核 —— 它写的是「不能做什么」，
但审核看的是字面。

Harness 的处理（三级降级，保证你总能收到回复）：

1. 摘掉底线提示词，重试
2. 缩短历史（保留最近几条），重试
3. 只发当前这条消息，重试

**注意**：降级的那一轮底线是不生效的 —— 它会短暂地「不守规矩」。
日志里会写明这次降级了。如果这类错误频繁出现，把底线措辞改含蓄一点。

## 12. 连接与掉线

默认走 WebSocket，本地程序主动连 QQ，不需要公网地址。

**连不上**：

- 检查 AppID / AppSecret 有没有填错（控制台会显示「已配置」）
- 检查事件订阅（Intents）里有没有勾上「接收消息」
- 检查网络能不能访问 `api.sgroup.qq.com` 和 `api.su.qq.com`

**掉线**：日志里会写关闭码。

| 码 | 意思 | 要不要管 |
| --- | --- | --- |
| 4006 / 4007 | 会话失效 | 正常，会自动重连 |
| 4009 | 连接过期 | **正常**，平台每隔一段时间就轮换一次，会自动恢复 |
| 1006 | 异常断开 | 网络抖动，会自动重连 |
| 4004 | 鉴权失败 | AppID / AppSecret 错了 |
| 4914 / 4915 | 机器人下架 / 封禁 | 得去平台处理 |

重连失败会按指数退避重试，控制台「概览」里能看到当前状态。

排查时开 `QQBOT_TRACE=1`，日志里会多出 `[trace] 开/关码` 这类细节。

## 13. 网络

**「第一次成功，之后全超时」** —— 大概率是代理没生效。

Node 的 `fetch` **默认不读** `HTTP_PROXY` / `HTTPS_PROXY`。
用 `NODE_USE_ENV_PROXY=1 npm run bot` 启动，QQ 接口、模型、联网搜索、生成都会走代理。

**搜索源**：DuckDuckGo → 必应 → 维基百科，自动回退。
DuckDuckGo 的中文结果最准；必应连得上但中文结果有时跑偏；维基百科在国内基本超时。
自动模式下单个源最多等 9 秒，连不上立刻换下一个。

**读不到某些网址**：有些站点直接拒绝非浏览器访问（HTTP 403），这很正常。

## 14. 界面风格

前端是原生 HTML / CSS / JS，没有构建步骤，改完刷新就生效
（`npm run dev` 的话后端也会自动重启）。

配色、圆角、间距这些都在 `public/style.css` 顶部的 CSS 变量里，
改一处就能全局换风格。深浅色主题跟着 `prefers-color-scheme` 自动切。

## 15. 开发者须知

**验证脚本不要碰真实数据。** `scripts/verify.mjs` 会自己建临时目录，
但如果你自己写脚本调 `new Store('./data')`，就会往你的真实库里写东西。

```js
// ❌ 会污染真实数据
const store = new Store('./data');

// ✅ 用临时目录
const store = new Store(mkdtempSync(join(tmpdir(), 'qqbot-')));
```

**发版前跑一遍** `npm run release:check`：它会查密钥有没有泄进代码、
查有没有写死个人路径、跑测试、查语法。

**误删的消息能捞回来吗？** 万一误删，`scripts/recover-messages.mjs` 能扫描
SQLite 的空闲页把已删除的记录找回来 —— 但它只对**还没被 secure_delete 覆盖**的
数据库有效，救回来之后记得赶紧备份。
