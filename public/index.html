  • 凭据有效不等于有全部权限：需在开放平台开通单聊 / 群聊 / 频道场景，并配置测试成员或发布机器人。

  • Webhook 必须配置公网 HTTPS 地址 https://你的域名/qq/webhook；官方允许回调端口 80 / 443 / 8080 / 8443。
    • 
              
  • 主动消息、被动回复的 msg_id / event_id、回复时限、条数与频率均受平台限制。

          


          
          

            

            

              
聊天模型
OpenAI 兼容或 Anthropic Messages 两种协议。对话内容会发送给你配置的服务。

                

              

                
                
                
                

                  
                  
                  
                

                
                
                
                
              

              

              
程序会追加 /chat/completions（OpenAI）或 /messages（Anthropic）。自动判断按地址识别：含 anthropic.com 或 claude 走 Anthropic，其余走 OpenAI。规则模式下不需要模型凭据。

            

            

              
图片 / 视频生成
不同服务的接入方式差别很大，这里提供三种，按需选择。

                

              

                
                
              

              

                

                  
                  

                    
                    
                    
                  

                  
                  
                

                
内置技能自带异步任务轮询与字段兼容处理。Key 留空时沿用聊天模型的 Key —— 聊天模型不是 Agnes 时请单独填写。

              

              

                

                  
                  
                  
                  
                  
                

                
适用于 Replicate / 硅基流动 / 豆包 / 即梦这类各自为政的服务。响应里取到的地址或 Base64 会直接作为生成结果使用；生图与生视频用同一套模板，靠 {{model}} 与 {{duration}} 区分。

              

              

            

          



          
          

            

              
语音开关
开启后机器人可以用 /语音 内容 发语音，模型也能主动调用 speak 工具。

                

                  
                  
                

              

                
                
                
                
              

              

            


            

              

                
合成接口
按服务商的协议选；不确定就先看「服务预设」。

                  

                    
                    
                  

                

                  

                    
                    

                      
                      
                      
                    

                    
                    
                    
                  

                  
从服务商账号里列出可用的音色 ID

                  

                    

                      
                      
                    

                    
MiniMax 的语音接口是 /v1/t2a_v2，和 OpenAI 的 /audio/speech 不是一回事；返回的音频是十六进制编码，程序已自动解码。失败时它仍返回 HTTP 200，真实错误藏在 base_resp.status_code 里，程序会翻译成可读的中文。

                  

                

                

                  

                    
                    
                    
                    
                    
                  

                  
响应里的音频可以是地址、Base64 或 十六进制，程序会自动识别。

              

            


            

              

                
Windows 系统语音
调用系统自带的 SAPI 引擎（PowerShell + System.Speech），不联网、不需要密钥。

                  

                

                  
                  
                  
                  
                

                

                
Windows 语音只在 Windows 上可用；本机没装 PowerShell 时会明确报错。合成结果为 16kHz 单声道 wav，QQ 直接接受。

              

            


            
关于语音消息
    
              
  • QQ 的语音消息是富媒体（file_type=3），接受 silk / mp3 / wav / ogg。
    • 
              
  • 转成 mp3 / ogg 需要本机装 ffmpeg；没有也能用 wav，只是文件大一些。
    • 
              
  • 语音只支持 QQ 单聊与群聊；频道和频道私信发不了。
    • 
              
  • 被动回复的名额有限：正文加语音会占掉一条，文字太多时程序会先合并正文腾位置。

长度与条数

              

                
                
                
              

              
字数是软目标，允许自然略超；过长回答会再次精简，不机械截字。QQ 单聊最多 4 条、群聊最多 5 条，单条硬上限 4000 字符。

            

            

              
节奏

              

                
                
                
                
                
                
                
                
              

              
首次回复延迟让机器人不再「秒回」：用户在窗口内连续发多条消息时，程序会把它们合并成一次提问再交给模型。斜杠命令不等待，立即回应。
